# 11+ content programme

Owner: Vim. Agreed 7 October 2026. Implementation is delivered in reviewable batches, not a bulk public release.

## Release policy

- Start with 3–5 substantial new pages per week as a planning ceiling, not an automatic quota or SEO guarantee.
- Prioritise corrections to existing facts before adding more advice.
- Every new/substantially changed educational page needs a current search-results review: intent, relevant competing URLs, entities, depth, original value and sources.
- Length follows the problem being solved; no mechanical competitor word-count target.
- Verify dates, school classification, exam provider, admissions stages and policies against official sources for the particular entry year.
- Document author/reviewer honestly. Never invent educator approval, parent testimonials, school affiliation or pass-rate promises.
- Check every original question and worked answer. Qualified educator review remains a release gate for the new lesson batch.
- Draft lessons are excluded from public routes, public links and sitemaps. Preview routes exist only in development or Vercel preview and are noindex.
- Release by an explicit reviewed status change in a later pull request; no unattended scheduled publication. Merging infrastructure must not release draft lessons.
- Approval of a batch does not imply approval of future batches. No automated task has been scheduled.

## Internal links

School → exam → suitable practice → worked answer → relevant topic → fresh practice. Topic lessons link to prerequisites and related skills. Do not expose links to unreleased drafts publicly.

## Acceptance record for each future batch

1. Primary and supporting search queries, search date and reviewed URLs.
2. Intent, page format, entities, observed depth and planned word-count range (with rationale).
3. Official fact sources and entry year where applicable.
4. Original contribution and duplication/cannibalisation check.
5. Answer verification and educator-review status.
6. Metadata, canonical, headings, relevant links and draft/public checks.
7. Build and functional validation; preview link; explicit release decision.
8. After release: indexing, impressions, useful visits, completed practice and repeat usage. Do not claim measured improvement without data.
